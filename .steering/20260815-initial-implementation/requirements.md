# 初回実装 要求内容: 撮影用インスタ画面メーカー

## 1. 目的

`docs/product-requirements.md` で定義した Phase 1 のスコープ(投稿詳細・プロフィール・フォロワー/フォロー一覧・フィード・ストーリーズ)を、実際に動作するFlutterアプリとして初回実装する。本作業の完了時点で、撮影現場のスタッフが各画面にダミーデータを入力し、プレビュー画面を撮影素材として使える状態にする。

## 2. 変更・追加する機能の説明

`docs/functional-design.md` で定義した以下のフィーチャーを、`docs/architecture.md` / `docs/repository-structure.md` の技術構成・フォルダ構成に従って実装する。

1. **プロジェクト基盤**
   - Flutterプロジェクトの初期化(`pubspec.yaml`、依存パッケージ導入)
   - Hive初期化処理、`TypeAdapter`登録、Box初期化
   - Riverpodの`ProviderScope`セットアップ、アプリ全体のテーマ(`AppTheme`)定義
2. **ホーム画面(`home`)**
   - 作成済みの投稿・プロフィール・フィード・ストーリーズグループの一覧表示
   - 各フィーチャーの新規作成への導線
3. **投稿(`post`)**
   - 投稿編集画面: 画像選択、キャプション・いいね数・投稿者名/アイコン・投稿時間ラベルの入力、コメントの追加/編集/削除
   - 投稿詳細プレビュー画面: 実機に近い見た目で表示。いいねアイコンのタップでトグル、コメント欄からのコメント追加が可能
4. **プロフィール(`profile`)**
   - プロフィール編集画面: プロフィール画像・名前・自己紹介文の入力、投稿サムネイルの追加/削除、フォロワー/フォローの追加/編集/削除
   - プロフィールプレビュー画面: 投稿数/フォロワー数/フォロー数の表示、各項目タップで対応する一覧画面へ遷移、投稿サムネイルのグリッド表示
5. **フォロワー一覧/フォロー一覧(`follow_list`)**
   - プロフィールに紐づくフォロワー一覧・フォロー一覧の表示(アイコン+名前のリスト)
6. **フィード(`feed`)**
   - フィード編集画面: 既存の投稿・ストーリーズグループから表示対象を選択し、並び順を設定
   - フィードプレビュー画面: 複数投稿のスクロール一覧、各投稿のいいね/コメント/シェアアイコン表示、ストーリーズアイコン列の表示とタップ遷移
7. **ストーリーズ(`story`)**
   - ストーリーズ編集画面: ストーリーズ所有者名・アイコン、複数枚の画像の追加/順序編集
   - ストーリーズプレビュー画面: 全画面表示、タップで次の画像へ送り、進捗バー表示

## 3. ユーザーストーリー

`docs/product-requirements.md` の「6. ユーザーストーリー」を、初回実装の対象範囲としてそのまま踏襲する(Phase 1の全ユーザーストーリーが本作業の対象)。

## 4. 受け入れ条件

`docs/product-requirements.md` の「7. 受け入れ条件」を初回実装の完了条件とする。加えて、本作業固有の受け入れ条件として以下を追加する。

- `flutter analyze` がエラー・警告なしで通ること
- 主要なNotifier(いいねトグル、コメント追加、フィード並び替え等)に対する単体テストが存在し、`flutter test` が通ること
- アプリを起動し、ホーム画面から5つの画面すべてに実際に遷移・データ入力・プレビュー表示ができること(手動確認)
- 入力したデータがアプリ再起動後も保持されていること(Hiveへの永続化が機能していること)

## 5. 制約事項

- 実装は `docs/architecture.md` で決定した技術スタック(Flutter / Riverpod(非コード生成) / Hive / 標準Navigator)に従う
- フォルダ構成は `docs/repository-structure.md` に厳密に従う
- コーディング・命名・スタイリング・テスト・Gitの各規約は `docs/development-guidelines.md` に従う
- ダークモード対応、動画対応、DM機能、有料課金機能は本作業のスコープ外(`docs/product-requirements.md` 10節のPhase外項目)
- 既存シリーズ(LINE版/X版)とのコード共有は行わない
