# 手順書: Android クローズドテスト移行

## 前提

以下は internal-testing の `release-guide.md`(`.steering/20260816-android-internal-testing/release-guide.md`)で既に完了済みの前提とする。

- リリース用キーストア・`android/key.properties` の作成(手順1〜2)
- `pubspec.yaml` のversionCode採番ルールの理解(手順3)
- `flutter build appbundle --release` でAABをビルドする手順(手順4)

未実施の場合は、先に上記リンク先の手順1〜4を行ってください。

## 1. バージョン番号の確認・更新

内部テストとクローズドテストは同じアプリ内の別トラックのため、versionCodeは共有の連番です。

1. Play Console の対象アプリ →「リリース」→「リリース履歴」で、直近使用済みのversionCodeを確認する(pubspec.yaml上の数値をそのまま信用しない — internal-testingで「既に使用されています」エラーが繰り返し発生した実績があるため)
2. `pubspec.yaml` の `version:` を `1.0.0+<次のversionCode>` に更新する
3. `flutter build appbundle --release` を実行し、AABを再生成する

## 2. クローズドテストトラックの作成

1. [Google Play Console](https://play.google.com/console) で対象アプリを開く
2. 左メニューの「テスト」→「クローズドテスト」を開く
3. 初回の場合、新しいトラックを作成する(例: 「クローズドテスト」)
4. 「新しいリリースを作成」→ ビルドしたAAB(`build/app/outputs/bundle/release/app-release.aab`)をアップロード
5. リリースノートを入力し、保存 → 確認 → クローズドテストとして公開

## 3. テスターリストの設定

以下いずれかの方法でテスターを登録する。

### 案A: メールアドレスのリストを直接登録
- 「テスター」タブ →「メールリストを作成」で対象者のメールアドレスをカンマ区切りで入力
- 少人数・すぐに開始したい場合に向いている

### 案B: Googleグループを作成して登録
- Google Groups で新しいグループを作成し、メンバーを追加
- Play Consoleの「テスター」タブでそのグループのメールアドレスを指定
- 人数の増減や管理をグループ側で行いたい場合に向いている

いずれの方法でも、登録後に発行される「テスト参加用リンク」をテスターに共有し、各自オプトイン(参加)してもらう必要がある。

## 4. 12人×14日間の要件について

Google Playの新規個人開発者アカウントは、本番(製品版)トラックへ公開する前に、クローズドテストで**最低12人のテスターが14日間継続してオプトインしている状態**を満たす必要がある(2026-08-24時点のポリシー。実施時にPlay Console上の表示で最新の要件を必ず確認すること)。

- **起算日の注意**: 14日間のカウントは「テスターが実際に参加(オプトイン)を開始した日」から始まる。リリースを公開した日ではない。テスターがリンクをクリックしてオプトインするまでは開始しないため、早めにテスターへ共有・依頼すること
- **進捗確認**: Play Console の「テスト」→「クローズドテスト」→ 該当トラックの「テスター」タブで、参加人数と参加開始日の状況を確認できる
- **12人に満たない場合**: テスターを追加で募る。内部テストの参加者に改めてクローズドテストへの参加を依頼してもよい(内部テストの参加実績はこのカウントに含まれない点に注意)

## 5. テスト参加用リンクの共有

内部テストと同様、「テスター」タブに表示される「テスト参加用リンク」をテスターに共有する。テスターはリンクからGoogle Playでアプリの参加に同意し、通常のPlayストア経由でインストールする。

## 6. トラブルシューティング

署名・ビルド関連のトラブルは internal-testing の `release-guide.md` の「6. トラブルシューティング」を参照。クローズドテスト特有の問題が発生した場合は、本セクションに追記していく。

- **「バージョンコードが既に使用されています」**: 内部テストとversionCodeを共有しているため発生しうる。手順1に従い、Play Console のリリース履歴で実際に次に使える番号を確認してから `pubspec.yaml` を更新する
- **テスターが「参加していません」と表示される**: テスト参加用リンクを開いて明示的に「テスターになる」を選択する必要がある。リンクを送っただけでは自動参加しない
